# 設計案：学習ログを書いてから理解度が変わるまでの流れ

一言でいうと：探す・検査する・PR にする手間を CLI と Claude に寄せ、本人は「判定して」「OK」の 2 回だけにする。その「OK」は、本人が自分の記憶で答えられる 2 つの問い（その出来事は本当にあったか／公開して困る言葉はないか）に絞る。

## 問題の捉え方

- **流れは通ったが、回っていない。** 2026-09-28 に 2 本通したきりで、その後の学習ログ（orgflow の 09-27・09-28。凍結後に変わったログ 4 本のうち未判定の 2 本）は判定されていない。
  今の `/judge-log` は 1 回の呼び出しで 1 本だけ判定し、1 本ごとに PR を作る。ログが溜まるほど手間が比例して増える
- **人の確認が形だけになっている。** 本人が「OK」と言ったのは Claude の要約で、`rationale`（判定の根拠の文）は 1〜2 文と短いのに読まれていない。
  原因は本人ではなく、「何を見れば OK と言えるか」が決まっていないこと。本人はコードの正しさを判断できないのと同じで、段（レベル）の妥当性も判断できない。
  判断できるのは「その出来事が実際にあったか」（本人はその場にいた）と「公開して困る言葉がないか」の 2 つ
- **機械にできる検査が人と AI に残っている。** 禁止語の grep、`evidenceRefs`（根拠の出どころ。ログの行を指す文字列）の行が実在するか、未判定ログの探索（git のコマンド 3 種を AI が毎回組み立てる）
- **本人が思い出さないと始まらない。** 学習は study で終わり、skill-matrix を開く動機がない。開いても「未判定が何本あるか」は `/judge-log` を回すまで分からない

論点は「どこまで自動化するか」ではなく、**人の確認を本人が答えられる問いに絞って小さくし、残りを CLI と Claude に渡す**こと。
守るべき線（API キーなし・ログ本文を置かない・判定は追記のみ・CI の `verify`・AI を信用しきらない）は 1 つも動かさない。

## 提案

### 流れ（1 回の学習から画面が変わるまで）

```
study のセッション
  本人 ①「ログを書いて」 → /study-log がログを書いてコミット（今のまま）
skill-matrix のセッション（ログ 1 本ごとでも、週 1 回まとめてでもよい）
  起動時フック …「未判定のログ 2 本（orgflow 09-27, 09-28）」を表示 → Claude が判定を提案
  本人 ②「判定して」
  Claude … pending（未判定を列挙）→ 全部を古い順に判定 → recalc → 検査（形・V1〜V8・禁止語・根拠の行の実在）
  Claude … 確認の 1 枚を出す（下の型）
  本人 ③「OK」 または 「3 番は違う。〜だった」
  Claude … 違うと言われた判定を外して recalc → コミット → PR → CI → 検品 → マージ   ← 本人は触らない
GitHub Pages … main への push で自動公開（本人が一度だけ Settings で有効にする）
```

本人がやるのは 1 回の学習につき **①②③ の 3 回**（skill-matrix では ②③ の 2 回）。まとめて判定すれば ②③ はログ 5 本でも 2 回のまま。
今も ②③ の 2 回だが、1 本ずつしか進まず、③ の中身が決まっていなかった。変わるのは「1 回で全部」「③ で何を見るか」「③ の後は本人が触らない」の 3 点。

### 誰が何を確かめるか

| 検査 | 今 | 提案 |
|---|---|---|
| 形の検査・V1〜V8・`state.json` の一致 | CLI `recalc` と CI `verify` | 変えない |
| 禁止語（所属・企業・面接・転職・人事） | AI が grep して報告。本人は見ない | `verify` に入れ、CI でも落とす（`recalc` でも出す） |
| `evidenceRefs` の行が実在し、`rationale` の出来事がその行にあるか | 誰も見ない | CLI `refs` がログの該当行を引いて並べ、本人が `rationale` と見比べる |
| その出来事が本当にあったか | 本人（Claude の要約で） | 本人（`rationale` 全文＋ログの行で） |
| 段（レベル）が妥当か | 本人（判断できない） | AI の目安のまま。`verifyBy` と保留（確信度 0.5 未満）で抑える。本人には問わない |
| 未判定のログの探索（3 つの除外規則） | AI が git を組み立てる | CLI `pending`（Go で書き、テストする） |
| PR の検品 | acceptance-reviewer が TODO の完了条件に照らす | 同じ役。データ PR 用の観点表（下）に照らす |

### 確認の 1 枚の型（③ で本人が見るもの）

判定 1 件につき次の 1 組。Claude の要約は入れず、**原文を並べる**。

```
3. react-hooks  drill  段 1  確信度 0.7
   根拠（rationale 全文）: ヒント無しの想起で、useEffect の用事と描画後に走ること…に正答した
   ログの行（study 09-27 #L8-L10）: 〔学習ログの原文。リポジトリに置かないため伏せた〕
```

末尾に 2 つの問いだけ置く：「この出来事は実際にありましたか（違う番号があれば番号と一言）」「公開して困る言葉はありますか」。
ログの行は study（Private）から引くので**チャットにだけ出し、PR 本文・コミットには書かない**。保留（確信度 0.5 未満）は「適用しない。採るなら番号で」と添える。

### データ PR の観点表（検品役が照らすもの）

TODO に完了条件が無いので、代わりに固定の 5 点：`data/judgments/` は新規ファイルだけ（既存の変更なし）／`state.json` は `recalc` の出力そのもの／
`verify` が OK／禁止語 0 件／PR 本文に本人の返答（「OK」または外した番号と理由）を原文で引用。これを `.claude/rules/judgment-pr.md` に置く。

### CLI に足す 2 つのサブコマンド（`recalc` / `verify` と同じ入口）

サブコマンドとは `git commit` の `commit` のように、1 つのコマンドの中の動作の名前。
- `pending --sources sources.local.json`：`prompts/judge.md` 手順 1〜3 の除外規則①②③をそのまま実装し、未判定のログを古い順に
  「repo / path / 判定に使うコミット / 読む範囲（全文か、どのコミットからの差分か）」で出す。git を呼ぶので CI では使わず手元だけ
- `refs <判定ファイル>`：`evidenceRefs` の `repo:` を手元のリポジトリで解決し、指した行を表示する。行が無ければエラー。手元だけ

どちらも「今日」に依存せず、`internal/domain` を汚さない（`cmd/` に置く）。AI が毎回 git を組み立てる今の手順は、CLI の呼び出し 1 行に置き換わる。

### 変える決まり（明示）

| 決まり | どう変えるか | なぜ |
|---|---|---|
| 判定の確認は `git diff`（SPEC §4.7） | 確認は上の「1 枚の型」。`git diff` は Claude が検品で使う | 本人が diff の JSON を読んで判断する前提が成り立っていない（事実 §4） |
| 禁止語の機械検査は事故が起きてから（台帳 2026-09-23 の見直し条件） | 事故を待たず `verify` に入れる | 目視が実際には行われていない。grep 1 本で済む |
| `/judge-log` は 1 回 1 本 | 未判定を全部、古い順に。上限 5 本で残りは件数を報告 | 溜まった分を 1 回で消化する。5 本はコンテキストの安全圏 |

変えないもの：API キーを置かない／ログ本文を置かない（`refs` の表示はチャット限り）／判定は追記のみ・`state.json` は `recalc` が書く／基準を指示書に書き写さない／V1〜V8／
技術的な事実だけ／画面は読むだけ／`main` は PR 経由（CI 5 ジョブ）／ChatGPT 経路（`judge.md` 末尾）は残すが自動化しない。

## 捨てた案

- **study のセッションの終わりに続けて判定まで回す**（①②を 1 回に）：skill-matrix の `CLAUDE.md`・フック・`sources.local.json` が読み込まれないセッションで判定を書くことになり、
  文脈が混ざる（`../CLAUDE.md`「既存アプリのディレクトリで新アプリを作らない」と同じ失敗の形）。代わりに skill-matrix 側の起動時フックで「未判定 n 本」を見せる
- **CI（GitHub Actions）が判定する**：Claude API のキーが要る。決まりに反する
- **CI が `recalc` を回して PR に積む**（TODO 2.5 の未確定）：本人の経路は Claude Code で、手元で `recalc` を回せる。ChatGPT などファイルを書けない経路のための仕組みなので v1.5 に残す
- **画面の「記録ページ」**（TODO 2.5 の未確定）：同上。画面が書き込み先を持つ方向に寄る
- **本人が GitHub の PR 画面で確認してマージする**：見る場所が増えるだけで、見る中身（JSON）は本人が判断できないまま。確認はチャットの 1 枚、マージは委任済みのとおり Claude
- **段の妥当性まで本人に問う**：判断材料が無い問いに答えさせると「OK」が空洞化する。段は `verifyBy`・保留・後からの `manual` 訂正で扱う
- **判定を貯めて週 1 回だけ PR**を決まりにする：頻度は本人の都合でよい。仕組みは「いつ呼んでも全部消化」にして頻度を縛らない

## リスク

- **③ の「OK」は依然として薄い。** 本人が見るのは出来事の有無と言葉で、段の過大評価は AI と `verifyBy` 頼み。対策：`manual` の訂正経路（SPEC §4.7）は残っており、画面で違和感があれば後から直せる
- **禁止語の grep は誤検出する**（「所属」の技術的な用法など）。`judge.md` 禁止事項に言い換えの指示が既にあり、`recalc` でも出すのでコミット前に直せる
- **`pending` が git を呼ぶ**ので、study が無い環境（CI・他人の Template 利用）では使えない。手元限定と明示し、`verify` からは呼ばない
- **一括判定で 1 回の会話が長くなる。** 上限 5 本で切り、残りは次回へ。判定ファイルは `<判定日>-<ログ日>-<題材>` なので日付順の適用は崩れない
- **起動時フックの表示は skill-matrix を開いたときだけ。** 開く習慣（週 1 など）は本人が決める。ダッシュボードにも同じ数を出す
- **データ PR でも CI は 5 ジョブ全部走る**（E2E 含む）。遅いが、ブランチ保護の必須チェック名を変えずに済ませる。遅さが問題になったら `paths` でジョブを分ける
- ChatGPT 経路（手貼り）は自動化しないため、使うなら今の手順のまま 5 つの材料を貼る。不便が実際に出たら貼り付け用の束を出すサブコマンド（台帳 2026-09-23 の保留案）を足す
- 自分で決めた点：ChatGPT 経路は使われていない（判定 9 本すべて claude-code）と見て後回しにした／未判定の本数は凍結コミット `284c0f1` 以後の差分から 2 本と数えた／
  本人が答えられる問いを「出来事の有無」と「公開して困る言葉」の 2 つに限ったのは、ブリーフ §1 の「コードの正しさは判断できない」を段の判断にも当てはめた推定

## 移行の手順

1 段階＝PR 1 本。上から順に、どれも今の判定ファイル・`state.json` を変えない。

1. **判定の確認を「1 枚の型」にし、`/judge-log` を一括にする（文書だけ）**：`prompts/judge.md` 手順 3・7 と `.claude/skills/judge-log/SKILL.md` を直す。
   `.claude/rules/judgment-pr.md`（データ PR の観点表）を置き、`CLAUDE.md` からリンク。SPEC §4.7 の「確認は `git diff`」を書き換える。ログの行は当面 AI が `git show` で引く
2. **禁止語を `verify` に入れる**：`data/judgments/*.json` の `rationale`・`evidenceRefs`・`unmatched` を検査し、該当があれば終了コード 1。`recalc` でも表示。単体テスト付き。
   わざと禁止語を入れた PR で CI が赤くなることを 1 度確かめる
3. **`pending` サブコマンド**：除外規則①②③と「読む範囲」の判定を Go に移し、一時的な git リポジトリを作るテストで確かめる。`judge.md` 手順 1〜3 を「`pending` を実行する」に置き換える
4. **`refs` サブコマンド**：`evidenceRefs` を解決して行を表示。無い行はエラー。`judge.md` 手順 6・7 で `refs` を使い、確認の 1 枚にログの行を載せる
5. **起動時フックとダッシュボードに「未判定 n 本」**：`.claude/hooks/` に `pending` を呼ぶ小さなスクリプトを置き、`dashboard/update.mjs` の数字タイルに 1 つ足す
6. **本人の操作 2 つ**（Claude は代行できない）：GitHub Pages の Source を GitHub Actions にする（付箋 `ops-dhj.4.1`）／新しい流れで orgflow 09-27・09-28 を最初に判定し、
   「1 枚の型」で答えてみる。答えにくい点があれば型を直す（ここが設計の検証）
7. （不便が出たときだけ）ChatGPT 向けの貼り付け用の束を出すサブコマンド。使われるまで着手しない
