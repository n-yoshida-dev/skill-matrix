- 未判定のログが既にたまっている。study の `orgflow-learning/logs/2026-09-27.md` と `2026-09-28.md` は 10-02 にコミットされたが、まだ判定されていない。
  判定は、本人が skill-matrix のセッションで `/judge-log` を思い出したときにしか走らない

  探し方の規則は試運転と受け入れレビューで 4 回穴が見つかり、文章で継ぎ足してきた（凍結・凍結後の追記・判定済みへの追記・glob。KNOWLEDGE.md 2026-09-27）

本人が確かめられること・確かめられないこと：

- できる：その場にいたので「自分の記憶と違う」に気づける。自分の勤め先・案件・人の名前のように、本人しか知らない「見せたくない言葉」に気づける

だから、人の確認を「本人にしか答えられない 2 点」に絞り、そのぶん残りを機械と別の AI で固める。

- **変える（決まりではなく手順）**：`judge.md` 手順 3「1 件選ぶ」→「古い順に最大 3 本」。判定ファイルは 1 ログ＝1 本のまま
- **採る**：確認待ち `ops-dhj.12` の (2)。pending は、ログの日付が凍結コミットの日以前なら「台帳に写っていない出来事だけ判定する」の印を付けて渡す（自動の探索でも書き起こしたログを全文判定しない）

## 捨てた案

- **study のセッションの終わりに、その場で判定する**（`/study-log` の続きで判定まで）：操作は 1 回減るが、教えた AI が自分の授業を採点することになり、
  ログに書かれていない会話の印象が判定に混ざる（`judge.md` ルール 1「ログに書かれていることだけ」が守れない）。1 つのセッションが 2 つのリポジトリに書き込む
- **CI（GitHub Actions）で AI に判定させる**：AI を呼ぶための鍵を GitHub に置くことになり、決まり「API キーを置かない」の趣旨に反する。
  Public のリポジトリのワークフローに Private の study を読む権限を渡すことにもなる。人の確認が PR の画面に移り、本人はそこを読まない
- **人の確認をなくし、検査が通れば自動でマージする**：本人しか知らない名前は、機械も照合役も知らない。公開した文は履歴から消しきれない（`logs/decisions.md` 2026-09-27）
- **今の決まりどおり、本人に `git diff` か PR で全文を読んでもらう**：本人の運用に合わず、09-28 に実際に要約で代わった。読む物を公開される文だけの表に絞るほうが続く
- **判定のたびに保留の採否を本人に聞く**：段の境目は本人が判断材料を持たない問い。保留は放置してよい決まり（SPEC §4.7）のままにする
- **画面の「記録ページ」と、CI が `recalc` して PR に積む仕組み**（TODO フェーズ 2.5 の【未確定】）：どちらも Claude Code を使わない人向け。
  本人は Claude Code が `recalc` まで回すので要らない。v1.5 のために捨てずに残す
- **study の `/study-log` の締めに「skill-matrix で判定を」と出す**：押し出す側として効くが、別リポジトリの運用に手を入れる。skill-matrix を開いたときに件数を出す側だけで足りるかを先に試す

## リスク

- 照合役も同じ系統の AI なので、同じ読み違いをしうる。独立しているのは「判定した会話を見ない」点だけ。役目を「書いてあるか」に絞って弱さを抑える
- 本人が表を読まずに「OK」と返す余地は残る。表を 12 行までにし、毎回「見てほしい 2 点」を添えて、読める量に保つ
- 禁止語の検査が拾うのは書いた語だけ。`privacy.local.json` は手元にしか無いので CI では効かず、書き忘れた名前は本人の目だけが頼り
- pending は study のログの置き方（`*/logs/*.md`、同じ日のファイルへの追記）に依存する。study 側の運用が変わったら、pending とそのテストも直す
- まとめて判定すると、同じ日付のファイルの並び（`judge.md` 手順 6 の逆順の問題）に当たりやすくなる。`recalc` 後の並びの確認は残す
- 照合役のぶん、1 回の判定でサブスクリプションの使用量が増える（判定とほぼ同じ量をもう 1 回）
- SessionStart フックで `go run` を走らせると、開くたびに数秒かかりうる。3 秒を超えるならダッシュボードの表示だけにする
- 本人が skill-matrix を開かない週が続けば、結局たまる。件数を見せるだけで、強制はしない
- 判断したこと：ブリーフは `orgflow-learning/logs/` を 5 本としているが手元では 32 本（凍結後に変わったのは 2 本）だったので手元の数を事実とし、本人が skill-matrix を開く頻度は週 1 回以上と仮定した
